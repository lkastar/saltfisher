## 一、被风控时不用盯面板

采集一被挑战，往**所有启用的渠道**发一条通知，正文是完整的五步操作。

走所有启用渠道、而不是规则关联的渠道：采集停的是全局，一条没关联渠道的规则否则会静默失败。
一次挑战只发一条，直到采集重新成功或重新导入凭证——`test_a_challenge_notifies_once_and_
the_next_cycle_stays_quiet` 和 `test_a_successful_collection_re_arms_the_alert` 两头钉住。

重新导入凭证后自动做两件事：清挑战标记，并**只**重新启用被风控停用的那些规则。手动停用的、
和连续失败 5 次停用的都不动——两类的 `last_error` 都带 `auto-disabled after N failures:`
前缀，只有 `needs verification:` 这段能把它们分开。

导入**不会**立刻触发采集。所有规则一起打上游，正是会被再次标记的那种请求量。

## 二、书签脚本：一次性票据，不是 API token

那段脚本在阿里控制的页面里执行，页面上的任何 JS 都能读到它发出的一切。所以它带的不是
`SFD_API_TOKEN`，是一张一次性票据：10 分钟、只能用一次、只开
`POST /api/session/cookies` 这一扇门。被从页面上偷走，最坏结果是替你导入一次 cookie。

几条不显然的决定：

- **票据在检查 payload 之前就被消费**。它授权一次*尝试*，不是一次*成功*——否则先发一坨垃圾
  再重试，票据就变成长期凭据了。
- **过期和无效是两条不同的消息**。这两者的区别就是「再点一次按钮」和「这个书签来路不对」。
- **CORS 写成路由级中间件**，不是 `CORSMiddleware`（那是整应用一档的），也不是在处理函数里
  加头。因为最需要被脚本读到的恰恰是**失败**响应：票据过期时若少了这个头，用户在闲鱼页面
  上只会看到一句「网络错误」。
- **票据只在进程内存里**。重启即全部作废，这是特性不是缺陷。
- `api/session.py` 因此成了全app唯一按路由声明鉴权的 router。这是个会漏的形状，所以
  `test_every_session_route_still_requires_something` 按 OpenAPI 路径清单断言每条路由都
  401——往这里加路由不写依赖会**挂测试**，而不是静默公开出去。

## 三、浏览器强加的两条，都在界面上说清楚而不是让它报 TypeError

### `#` 和 `?` 都会静默截断 `javascript:` URL

书签是先被当 URL 解析、再被求值的。`#` 开片段、`?` 开查询，第一个之后的东西在脚本运行前
就没了，点下去毫无反应、哪里也不报错。

第一版里是一个 CSS 十六进制色号带进了 `#`；改掉之后，第二版里消息逻辑的三元运算符带进了
`?`。**两次都是我写的测试自己抓到的**——但第一版那个测试写的是"不许出现 `#`"，只能抓住它
认识的那个字符。现在改成把三个危险字符（`%` `#` `?`）全部百分号编码，断言也换成「这个 URL
经解析后一字不丢、解码回来能被 `new Function` 解析」，不再依赖一份字符黑名单跟得上。

### https 页面 fetch 不到明文 http 面板

混合内容，浏览器拦的，后端加什么头都绕不过去；`localhost` / `127.0.0.1` 是唯一例外。
这个能精确检测，所以设置页直接检测 `location.protocol` 并把按钮置灰、写明原因，
而不是等用户点下去收一个 `TypeError`。

顺带加了 `Access-Control-Allow-Private-Network: true`：goofish 是公网、面板在私有地址，
Chrome 按 Private Network Access 预检，不授权直接丢弃请求。

## 四、一条会让这个功能变成陷阱的错误研究结论

`research/cookie-domains.md` 原本写着：闲鱼页面读不到 `_m_h5_tk`（它只在 `.taobao.com`
上）**不要紧**，因为 `TokenStaleError` 的注释说「Recoverable WITHOUT human help」——报
token 过期的那个响应自己带着新 token，吸收了重试即可。

**结论对，理由错，而且照它实现会出事。**

轮换只能换掉一个*已经存在*的 token。`mtop.py` 在签名之前就有
`if not token: raise ChallengeError("no _m_h5_tk: session not established")`——一个都没有
时根本发不出请求，也就收不到那个"带着新 token 的错误响应"。照原文实现会得到：
书签报导入成功 → 第一个周期 `ChallengeError` → 风控类第 1 次失败就停用**全部**规则。
一个报成功然后把你所有监控关掉的按钮。

真正补上第一个 token 的是**浏览器兜底**：`pipeline.py` 看到 `not session.usable` 就走
Playwright，真实页面加载时闲鱼自己的 JS 会去领一个 `_m_h5_tk`，`_adopt_session()` 再把它
交回内存会话。代价是书签导入后的第一个周期慢、且只覆盖第 1 页，之后回到便宜的 mtop 路径。

已在四处更正：研究笔记、`spec/backend/collector-guidelines.md`、`mtop.py` 那个 raise 上方，
以及 `docs/operations.md`。并由
`test_a_tokenless_import_routes_to_the_browser_and_recovers_there` 钉住——把
`pipeline.py` 的兜底分支删掉，它立刻从 `(0,1)` 变 `(1,0)` 报红（已实测）。

设置页也直说了：书签导入后显示「会话不可用 · no _m_h5_tk」是**预期的**，不是导入失败。

## 五、我犯的错

- **上面那条研究结论是我自己写的**，而且我在 P6 的任务简报里把它当既定事实交给了实现方。
  它读起来完全可信：引了具体行号、引了真实的代码注释、结论也确实成立。错的是中间那步。
- **被派去做 T2 的 agent 死于 API 错误**，但它已经把代码写在盘上了。我先读了一遍再决定
  救而不是重做——那份代码质量很高，唯一的问题是它**自己写的测试自己没跑**，那条"空格"断言
  是它的代码不可能满足的（`var U=`、`return r.json()` 都是字面量外的空格），而且那条规则
  本身就是假的（`javascript:` URL 求值前会被百分号解码）。换成真正吃重的断言之后，
  才炸出了 `?` 那个截断。
- **60 个测试报 401 我一开始以为是回归**。实际是开发机 shell 里 export 了真的
  `SFD_API_TOKEN`，而 conftest 用的是 `setdefault`，真 token 赢了。顺手改成直接赋值——
  这个失败模式最坏的地方是它长得像鉴权坏了，而且什么都不指向。
- `docs/architecture.md` 里的接口计数写着 19 条路径 27 个操作，实际是 29 / 40。
  我上一轮"更正"过它一次。这次的数字是当场从 `app.openapi()` 数的，并且标了日期。

## 六、不做滑块转发

用户问的是「转发滑块验证」。这条不做，重申一次理由：

把一个验证挑战搬出它的来源、送到别处去解，好让一个自动采集器解除封锁——不管解的是人还是
程序，这都是绕过机器人检测。这个项目不做这件事。

滑块只能你自己在浏览器里过。书签脚本做的事，是在你**已经登录、已经过完滑块之后**，省掉
复制粘贴那一步。它不接触挑战本身。
